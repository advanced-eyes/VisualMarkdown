# 시각화 시험용 예시

모든 보기(지식 사이 · 지식 안)를 한 번에 시험하는 wiki 다. `wiki/` 를 그대로 Obsidian 볼트나 VS Code 폴더로 열 수 있다. 보기 앱([README §3.1](../../README.md#31-보기-앱으로-보기))은 폴더를 주지 않으면 이 wiki 를 연다. 아래 기대값은 색인 · 배치 · 차트 · 위젯 · 보기 앱 시험이 확인한다.

- 내용: 객체 검출 논문 4편(YOLO · YOLO9000 · YOLOv3 · Focal Loss), 손으로 정리한 노트 1편(2단계 검출기), 가상의 기획서 1편(결제 서비스). 논문 숫자는 원문의 표와 초록에서 옮겼다(설명용). 기획서와 그 숫자는 지어낸 것이다.
- 모든 파일은 라이브러리가 쓰는 정준 모양이다. `tests/ShowcaseWikiTest.cpp` 가 읽고 다시 쓰면 바이트가 같은지와 이 문서의 기대값을 확인한다.
- 기대값은 색인 규칙([format/Visualization.md §2](../../format/Visualization.md#2-색인--파일에서-그래프로))대로 센 것이다.
- [examples/wiki](../wiki/) 는 형식 문서에 붙은 작은 정준 예시이고, 이 폴더는 보기를 시험하는 예시다.

## 4. 형식 경계 사례

보기와 읽기에서 함께 확인할 것이다.

- 카드: id 없는 카드(2단계 노트의 둘째 카드), 모르는 하위 항목 `메모:`(YOLO 의 둘째 카드), 개념 이름과 다른 링크 글자(`Region Proposal Network` → 개념 RPN)
- 핵심 숫자: 단위 없는 것(`**9000** — …`), 단위가 `%` 인 것
- 문서 머리글: AI 가 분석한 문서 5편, 손으로 쓴 노트 1편(`rules: 0`, `edited: true`, `analysis` 없음)
- 빈 정해진 절: 핵심 숫자가 없는 문서(2단계 노트), 데이터가 없는 문서(Focal Loss)
- 개념: 별칭이 있는 것 11개 · 없는 것, 연도가 없는 것, `## 관계` 가 있는 개념 파일 11개
- 한국어 파일 이름과 id(`1단계-검출기`, `roi-풀링`, `결제-모듈-2판`)

## 5. 고칠 때

- 정해진 부분을 고치면 `digest` 를 다시 계산한다([ReadWrite.md §6](../../format/ReadWrite.md#6-digest)).
- 기대값이 바뀌면 이 문서와 `tests/ShowcaseWikiTest.cpp` 를 같은 커밋에서 고친다. 문서 · 표가 바뀌면 보기 앱 스냅샷의 기대 목록 `tests/viewer/showcase-snapshot.tsv` 도 고친다.
- 라이브러리에 새 보기 · 차트 종류 · 보기가 읽는 칸을 더하면, 그 경우를 이 wiki 에 더한다([README §9](../../README.md#9-바꾸는-규칙)). §1 표의 "시험하는 것" 과 §2 · §3 의 기대값도 함께 고친다. 이 wiki 가 모든 시각화를 한 번에 시험한다는 약속을 지키려는 것이다.
