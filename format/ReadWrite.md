# 읽기 · 쓰기

다른 편집기에서 고친 파일을 너그럽게 읽고, 고친 글을 잃지 않게 쓰는 규칙이다.

## 1. 줄과 범위

- 읽기 전에 맨 앞 BOM 을 빼고 `\r\n` 을 `\n` 으로 바꾼다. 그다음 줄 단위로 훑는다. 마크다운 파서를 쓰지 않는다.
- **머리글**: 첫 줄이 `---` 면 다음 `---` 줄까지다. 머리글이 없거나 닫히지 않았거나, `type` 이 다르거나 `id` 가 없으면 그 파일은 읽지 않는다(오류를 로그에 남긴다).
- **제목**: 첫 `##` 앞의 첫 `# ` 줄.
- **절**: `## ` 줄부터 다음 `## ` 줄 앞까지. 절 이름은 `## ` 뒤의 글이다(앞뒤 공백은 빼고 이어진 공백은 하나로 접는다).
- 코드 울타리(```` ``` ```` · `~~~`) 안의 줄은 제목 · 절로 보지 않는다.
- 정해진 절 안의 줄은 그 절의 문법으로 읽는다. 링크 대상은 줄 원문에서 읽는다.

## 2. 제목과 한 줄

한 줄(문서는 요약, 개념은 정의)은 제목과 첫 `##` 사이에서 처음 만나는 **보통 문단**이다.

- 아래로 시작하는 덩어리는 건너뛰고 손대지 않는다: 그림(`![`), 인용(`>`), 목록 항목(`- ` `* ` `+ ` `1. ` `1) `), 표(`|`), HTML(`<`), 코드 울타리, 가로줄(`---` `***` `___`), 제목(`#`).
- 건너뛴 덩어리는 다음 빈 줄, 또는 제목 · 가로줄 · 한 줄 HTML 주석 · 코드 울타리 줄 앞까지다. 울타리는 닫는 줄까지, 제목 · 가로줄 · 한 줄 HTML 주석(`<!-- … -->`)은 그 줄만이다.
- 문단은 빈 줄이나 위 덩어리를 여는 줄에서 끝난다. 여러 줄이면 공백 하나로 이어 읽는다.
- 다시 쓸 때는 그 문단의 줄만 바꾼다. 앞뒤의 그림 · 인용 · 메모는 자리 그대로 남는다.
- 쓸 한 줄이 위 덩어리를 여는 글자로 시작하면 GFM 백슬래시 이스케이프 하나를 붙인다: `\<` `\>` `\|` `\!` `\-` `\*` `\+` `\#` `` \` `` `\~` `\_`, 번호 목록은 숫자 뒤(`1\.` · `1\)`). 읽을 때 그 `\` 하나만 뺀다. 그래서 한 줄은 글자 그대로 왕복하고 다른 편집기에서는 이스케이프 없이 보인다. 이미 그 꼴인 글(`\- …`)은 `\` 를 하나 더 붙인다.

## 3. 머리글

- 키는 첫 `:` 앞, 값은 뒤다. 값은 한 줄이고, 앞뒤 공백은 빼고 이어진 공백은 하나로 접는다(따옴표 안도 같다). 쓸 때 줄바꿈은 공백 하나로 바꾼다.
- YAML 의 흔한 모양도 읽는다(Obsidian 속성 창이 고쳐 쓴 파일):
  - 따옴표: `"…"` 는 `\"` · `\\` 를 되돌리고, `'…'` 는 `''` 를 되돌린다. 앞뒤를 감싼 따옴표 한 쌍이 아니면 글자 그대로다.
  - 목록: 블록 목록(`aliases:` 다음 줄마다 `  - 별칭`)과 흐름 목록(`aliases: [a, b]`)을 읽는다. 목록 항목 안의 쉼표는 나누지 않는다.
  - **목록으로 읽는 키는 `aliases` 뿐이다.** 다른 키의 `[…]` 값은 글자 그대로 한 값이다(`meta: [초안] 3쪽`).
- 다시 쓸 때 아는 키는 있던 모양을 지킨다. 블록 목록은 블록 목록(키 줄과 항목 줄을 통째로 바꾼다), 흐름 목록은 흐름 목록, 따옴표 값은 그 따옴표로 쓴다. 목록 키가 아닌 키를 목록으로 적었으면 한 값으로 쓴다.
- 따옴표 없이 쓰면 YAML 이 다르게 읽는 값은 큰따옴표로 감싸 쓴다(`\` → `\\`, `"` → `\"`): `: ` · ` #` 가 들어 있거나, `:` 로 끝나거나, `- ? : , [ ] { } # & * ! | > ' " % @` 와 `` ` `` 중 하나로 시작하는 값.

## 4. 이스케이프

| 자리 | 쓸 때 | 읽을 때 |
| --- | --- | --- |
| 링크 글자 | `\` `[` `]` 앞에 `\` | `\x` → `x` |
| 링크 경로 | 글자 그대로 | `%XX` 되돌림([Folder.md §4](Folder.md#4-링크)) |
| 표 칸 | 칸 안의 세로 막대 앞에 `\` | `\` + 세로 막대 → 세로 막대 |
| `ocean:data` 속성 값 | `&` → `&amp;`, `"` → `&quot;`, `>` → `&gt;` | 되돌림 |
| 한 줄 · 정의 | 블록을 여는 글자 앞에 `\` 하나(§2) | 그 `\` 하나 뺌 |
| 머리글 값 | YAML 에 안전하지 않으면 큰따옴표(§3) | 따옴표 벗김 |
| 머리글 값 · 하위 항목 · 주장 · 칸 | 줄바꿈 → 공백 하나 | — |

## 5. 쓰기

- 새 파일은 정해진 순서로 전부 쓴다(문서: [DocumentFile.md](DocumentFile.md), 개념: [ConceptFile.md](ConceptFile.md)).
- 있는 파일은:
  - 머리글: 아는 키만 바꾸고, 모르는 키 줄은 그대로 둔다.
  - 정해진 부분(제목 · 한 줄 · 정해진 절)은 다시 쓴다. 그 밖의 줄은 손대지 않는다.
  - 없던 정해진 절은 순서상 알맞은 자리(앞 정해진 절 바로 뒤, 없으면 한 줄 문단 뒤)에 넣는다. 한 줄 문단 뒤에 사용자 줄이 이어지면 그 줄들 뒤에 넣는다.
  - 정해진 절 안의 읽지 못한 줄은 그 절 끝에 쓴다([DocumentFile.md §7](DocumentFile.md#7-읽지-못한-줄)).
- UTF-8(BOM 없음), 줄 끝 LF, 파일 끝 줄바꿈 하나.
- 임시 파일에 쓴 뒤 바꿔 넣는다. 쓰다 멈춰도 옛 파일이 남는다.
- 개념 파일을 먼저 쓰고 문서 파일을 쓴다. 없는 개념을 가리키는 순간이 없게 하려는 것이다.
- **왕복**: 라이브러리가 쓴 파일을 읽어 그대로 다시 쓰면 바이트가 같다(차례 번호가 빈 항목은 예외, §8).

## 6. digest

문서 파일 머리글 `digest` 는 라이브러리가 마지막으로 쓴 정해진 부분의 SHA-256(16진수 소문자 64자리)이다. 다른 프로그램에서 고쳤는지 알아챌 때 쓴다.

- 계산하는 글은 **정준 글**이다. 정해진 부분만으로 새 파일을 쓸 때의 본문 그대로다: `# 제목` 줄부터 마지막 정해진 절의 끝 줄까지. 덩어리(제목 · 한 줄 · 각 절 · 각 표) 사이에 빈 줄 하나, 줄 끝 `\n`, 끝에 `\n` 하나. UTF-8 로 바꿔 해시한다.
- 그래서 정해진 부분 밖을 고친 것, 빈 줄 · 들여쓰기 같은 모양만 다른 것은 바뀐 것으로 치지 않는다.
- 쓸 때마다 새로 계산해 머리글에 쓴다.
- 다시 저장할 때 지금 파일의 정해진 부분으로 계산한 값이 `digest` 와 다르거나 `edited: true` 면 덮어쓰기 경고를 띄운다.
- 개념 파일에는 `digest` 가 없다.
- 정해진 부분만 있는 파일(예: [examples/wiki](../examples/wiki/))은 닫는 `---` 뒤 빈 줄 다음부터 파일 끝까지가 정준 글이다.

## 7. 다른 프로그램이 고친 파일

- 라이브러리는 `ReloadIfChanged(문서 id)` 로, 마지막으로 읽은 뒤 그 문서 파일의 수정 시각이 바뀌었으면 다시 읽는다. 언제 부를지는 앱이 정한다(Ocean 은 지금 앱을 켤 때 `Reload` 로 전부 읽는다). 개념 파일은 `Reload` 때만 다시 읽는다.
- 수정 시각은 파일을 읽기 **전에** 잰다. 읽는 사이 바뀐 것을 다음에 알아채려는 것이다.
- 파일 감시는 없다. 다른 프로그램에서 고치는 중에 같은 파일을 쓰면 나중 쓰기가 이긴다. 정해진 부분만 다시 쓰므로 그 밖의 글은 지켜진다.
- 머리글 `format` 이 아는 판보다 높으면 아는 것만 읽고 그 파일은 다시 쓰지 않는다(읽기 전용).

손으로 고칠 때 남는 것과 바뀌는 것

| 고친 것 | 다시 쓴 뒤 |
| --- | --- |
| 정해진 절 밖의 절 · 글 · 그림 | 자리 그대로 |
| 모르는 머리글 키 | 그대로 |
| 카드 · 관계 아래 `  - 메모` | 그 항목 아래 그대로 |
| 정해진 절 안의 문법 밖 줄 | 글자 그대로, 그 절 끝으로 옮겨짐 |
| `ocean:data` 의 모르는 속성 | 사라짐(이름에 `-` 가 있으면 다른 값을 덮을 수 있다, §8) |
| 카드 `개념:` 줄의 `[[위키 링크]]` | 사라짐 |
| 정해진 부분의 내용(주장 · 관계 · 표 값) | 새 값으로 바뀜(덮어쓰기 경고 뒤) |

## 8. 알려진 한계

Ocean 계획 ② 의 남은 백로그다. 고치면 이 목록에서 지운다.

- 표가 끝난 뒤(빈 줄 뒤)의 `ocean:data` 주석은 읽지 않는다. 블록 어디서든 읽거나 "주석은 표 앞" 을 문법으로 굳힌다.
- 주석만 있고 표가 없는 `###` 블록은 0열 표가 된다. 진짜 머리 줄이 있을 때만 표로 봐야 한다.
- 인용 속 공백으로 묶은 숫자가 앞의 숫자를 삼킨다(`Figure 3 416` → `3416`). Ocean 검사기 경고에만 영향이 있다.
- Obsidian 위키 링크 `[[YOLO]]` 는 읽지 않고, 카드 `개념:` 줄에 있으면 다시 쓸 때 사라진다.
- `#태그` 로 시작하는 한 줄은 `\#태그` 로 쓰인다. 여러 줄 `<!--` 주석은 다음 빈 줄까지만 건너뛴다.
- 표 칸은 글자라서 `63.4±0.2` 같은 값은 수치가 되지 않는다(그 열은 범주가 된다).

2단계(라이브러리로 옮기기)의 검증에서 찾은 것이다. 옮기기는 동작을 바꾸지 않으므로 그대로 두었다. 고치면 동작이 바뀌므로 Ocean 과 함께 고친다.

- `ocean:data` 속성 이름이 `-` 를 품으면 `-` 뒤 부분이 아는 속성으로 읽힌다(`data-x="c"` 가 `x` 를 덮는다). 속성 이름 앞에 공백을 요구하면 고쳐진다.
- 개념 · 문서 id 는 60 UTF-16 단위에서 잘린다. 경계에 걸린 이모지는 반쪽이 남고, 그 링크는 다시 읽으면 id 가 달라져 그래프에서 빠진다.
- 차례 번호가 빈 항목은 `- 제목` 으로 쓰이고, 다시 읽으면 읽지 못한 줄이 된다(쓰고 다시 읽은 기록이 달라지고 `digest` 도 바뀐다).
- 빈 열 이름은 이름 정리 뒤에도 쓰고 다시 읽으면 달라진다: 단위만 있는 빈 이름 ` (u)` 는 이름 `(u)` 로, 겹친 빈 이름 ` 2` 는 `2` 로 읽히고, 빈 이름을 가리키는 `y` · `ordered` 항목은 빠진다.
- 공백 · 제어 문자는 ASCII 기준이다([Folder.md §2](Folder.md#2-개념-id)). 그래서 U+00A0 같은 공백이 든 이름은 같은 개념으로 이어지지 않을 수 있다.
