# 파일에서 그래프로

## 1. 두 층

| 층 | 그리는 것 | 파일에서 읽는 곳 |
| --- | --- | --- |
| **지식 사이** | 점 = 개념, 선 = 관계 | 개념 파일(점), 문서 · 개념 파일의 `## 관계`(선), 카드 `개념:` · 표 `concepts`(문서 ↔ 개념 연결) |
| **지식 안** | 한 표의 행 · 열 → 차트 | 문서 파일 `## 데이터` 의 `ocean:data` 주석과 표 |

- 두 층 모두 이 폴더의 형식만 읽는다. 보기는 늘어나도 파일 규칙은 하나다.
- 보기는 파일을 직접 읽지 않고 **색인**에 묻는다(§2).

## 2. 색인 — 파일에서 그래프로

라이브러리의 `KnowledgeBase` 가 `wiki/` 를 읽어 메모리에 만든다.

**점(개념)**
- 개념 파일 하나가 점 하나다. id 는 파일 이름이다.
- 이름과 별칭을 이름 열쇠로 색인한다([ConceptFile.md §4](ConceptFile.md#4-같은-개념인지-보는-법)).
- 문서마다 그 문서가 가리키는 개념을 모은다: 카드 `개념:` 의 링크, 관계의 from · to, 표의 `concepts`. 한 문서는 한 개념을 한 번만 센다. 이 수가 "이 개념을 다루는 문서 수"다.
- 어떤 문서도 가리키지 않고 개념 파일의 관계에도 나오지 않는 개념은 숨긴다.

**선(관계)**
- 문서 파일과 개념 파일의 관계를 모두 모은다.
- (from · 종류 · to) 가 같으면 선 하나로 합친다. 방향 없는 종류는 두 id 를 글자 순으로 놓고 합친다(A ↔ B = B ↔ A).
- 합친 선의 상태는, 하나라도 확인됨이면 확인됨이다.
- 합친 선은 출처를 갖는다: 그 관계를 말한 문서 id 들, 개념 파일에서 왔는지.
- from 이나 to 의 개념 파일이 없으면 그 선은 넣지 않고 로그에 남긴다.

**문서**
- 문서 목록은 머리글 `learned` 가 늦은 것부터 준다(같으면 id 순).

색인이 주는 것(지금 Ocean 코드의 공개 함수)

| 함수 | 주는 것 |
| --- | --- |
| `ListConcepts(includeHidden)` | 점 목록(이름 열쇠 순) |
| `FindConcept(id)` · `FindConceptIdByName(nameOrAlias)` | 점 하나 |
| `ListRelations()` | 합친 선 목록: from id · 종류 · to id · 상태 · 출처 문서 id 들 · 개념 파일에서 왔는지 |
| `ListDocuments()` · `FindDocument(id)` | 문서 기록: 카드 · 관계 · 표 |
| `ListKnownConcepts()` | 점마다 이름 · 별칭 · 종류 · 다루는 문서 수 |

## 3. 지식 사이 보기가 쓸 수 있는 칸

스펙이 이름을 든 보기와, 그 보기가 읽을 수 있는 칸이다. 보기 자체는 아직 정하지 않았다(README §10).

| 보기 | 쓰는 칸 |
| --- | --- |
| 관계망 | 점: 개념 · `kind`(묶기 · 모양). 선: 관계 종류 · 방향 · 상태(AI 제안은 흐리게 등) |
| 계보도 | `improves`(새것 → 옛것), `year` |
| 분류 트리 | `isA`(하위 → 상위). 계열 · 분류는 따로 칸이 없고 이 관계에서 나온다 |
| 타임라인 | `year`, 갈래는 `isA` · `improves` |
| 관계 행렬 | 개념 × 개념, 칸 = 관계 종류 |
| 문서 ↔ 개념 | 카드 `개념:`, 표 `concepts`, 관계의 출처 문서 |

- B 가 A 를 개선했다면 B 를 볼 때 A 와 "무엇을 고쳤는지"(관계의 `설명`)가 함께 보이게 하는 것이 목표다.

## 4. 지식 안 보기가 쓸 수 있는 칸

| 칸 | 뜻 |
| --- | --- |
| `x` | 가로축이 될 기준 열 |
| `y` | 비교할 수치 열들 |
| `series` | 계열로 나눌 열 |
| 열 종류 | 수치 · 순서 · 범주([DataTable.md §4](DataTable.md#4-열-종류--읽을-때-정한다)) |
| 단위 | 머리 칸 `(…)` 에서. 축 이름표에 |
| `cumulative` | 앞 행에 하나씩 더한 단계 표 |
| `condition` · `where` | 측정 조건 · 원문 자리. 차트 밑글에 |

차트를 고르는 시작점(**제안**, 정하지 않음). 2026-10-22 시험에서 열 종류로 고른 추천 차트가 사용자가 고를 차트와 다르지 않았다. 규칙은 보기 스펙에서 정한다.

| x 열 종류 | 그 밖 | 시작 차트 |
| --- | --- | --- |
| 범주 | | 막대 |
| 순서 | `cumulative` | 단계 막대(앞 행과의 차이) |
| 순서 | | 선 |
| 수치 | | 산점도. `series` 가 있으면 계열마다 색을 나눈다 |
| 아무것 | `y` 가 여럿 | 같은 x 에 y 마다 막대 · 선을 나란히 |

## 5. 보기 정보는 파일에 넣지 않는다

- 점 위치, 색, 고른 차트, 접은 갈래 같은 보기 정보는 지식 파일에 쓰지 않는다. 데이터와 보기를 떼어 놓으려는 것이다(2026-10-22 사용자 결정).
- 어디에 둘지는 아직 정하지 않았다.
- `ocean:data` 에 보기 속성을 더하지 않는다. 다시 쓰면 사라진다.

## 6. 정하지 않은 것

- 보기 화면과 차트 추천 규칙(§3 · §4)
- AI 제안 관계를 확인 · 고치는 화면
- 여러 문서의 표 행을 모아 지식 사이 보기에서 비교하는 규칙
- 보기 정보를 둘 곳(§5)
