# 개념 파일 — 그래프의 점

개념 하나 = 파일 하나. 여러 문서가 같은 개념을 다루면 한 파일로 모인다.

```markdown
---
type: concept
format: 1
id: yolov2
kind: method
aliases: YOLO9000
year: 2017
---

# YOLOv2

YOLO 에 anchor · 배치 정규화 등을 더해 정확도를 끌어올린 판

## 관계

- [YOLOv2](yolov2.md) **종류** → [1단계 검출기](1단계-검출기.md)
```

## 1. 머리글

| 키 | 값 | 없으면 |
| --- | --- | --- |
| `type` | `concept` | 파일을 읽지 않는다 |
| `format` | 형식 판([Vocabulary.md §5](Vocabulary.md#5-판)) | `1` |
| `id` | 개념 id. 파일 이름과 다르면 파일 이름이 이긴다([Folder.md §2](Folder.md#2-개념-id)) | 파일을 읽지 않는다 |
| `kind` | 개념 종류 코드([Vocabulary.md §1](Vocabulary.md#1-개념-종류)). 이름(`방법`)도 읽는다 | 빈 종류 |
| `aliases` | 다른 이름, 쉼표로 여럿. YAML 목록도 읽는다([ReadWrite.md §3](ReadWrite.md#3-머리글)) | 별칭 없음 |
| `year` | 네 자리 숫자. 그 밖의 값은 없는 것으로 읽는다 | 연도 없음. 모르면 줄을 쓰지 않는다 |

- 별칭 안에는 쉼표를 쓰지 않는다(한 줄로 쓴 `aliases` 는 쉼표에서 나뉜다).
- 모르는 머리글 키는 읽지 않지만 다시 쓸 때 그대로 남는다.

## 2. 본문

| 자리 | 뜻 |
| --- | --- |
| 첫 `# ` 제목 | 이름 |
| 제목 아래 첫 보통 문단 | 정의. 고르는 법은 [ReadWrite.md §2](ReadWrite.md#2-제목과-한-줄) |
| `## 관계` | 사람이 직접 적은 관계(문서에 매이지 않은 것). 문법은 [Relation.md](Relation.md). 링크는 `<id>.md` |
| 그 밖의 절 · 글 | 읽지 않는다. 자유롭게 쓴다 |

- 라이브러리는 개념 파일의 `## 관계` 를 읽기만 한다. 다시 쓸 때 그 절은 사용자 글처럼 그대로 둔다.

## 3. 파일에 적지 않는 것

- 그 개념을 다루는 문서 목록, 들어오는 관계. 읽을 때 모은다([Visualization.md](Visualization.md)).
- 보기 정보(점 위치 · 색).

## 4. 같은 개념인지 보는 법

- **이름 열쇠**: NFC 정규화 → 소문자 → 공백 · `-` 를 모두 뺀 글자. `Faster R-CNN` · `faster rcnn` · `Faster-RCNN` 은 열쇠가 같다.
- 개념의 이름과 별칭이 모두 열쇠가 된다. 열쇠가 겹치면 id 순으로 앞선 개념이 그 열쇠를 갖는다.
- 새 문서의 개념은 열쇠로 있는 개념을 찾아 잇고, 없을 때만 새 파일을 만든다. 이은 개념에는 새 이름을 별칭으로 더한다.
- 이은 개념의 정의 · 연도 · 종류는 비어 있을 때만 채운다. 다른 문서가 다른 정의를 줘도 바꾸지 않는다.

## 5. 지우지 않는다

- 개념 파일은 자동으로 지우지 않는다. 문서를 지워도 개념 파일은 남는다.
- 어떤 문서도 가리키지 않고 손으로 적은 관계에도 나오지 않는 개념은 **숨은 개념**이다. 목록 · 보기에서 숨긴다.
