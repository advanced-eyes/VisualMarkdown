## 1. 머리글

| 키 | 값 |
| --- | --- |
| `type` | `document`. 다르면 파일을 읽지 않는다 |
| `format` | 형식 판([Vocabulary.md §5](Vocabulary.md#5-판)). 없으면 `1`. 여러 줄 근거(§5.1)가 있는 문서만 `2`, 나머지는 `1` 로 쓴다 |
| `id` | 문서 id(UUID). 없으면 파일을 읽지 않는다 |
| `source` | 원문 파일 이름 |
| `fileInfo` | "PDF 15쪽" · "Markdown 838줄" · "텍스트 120줄" |
| `meta` | 저자 · 학회 · 연도 같은 한 줄 정보 |
| `learned` | 저장한 시각(ISO 8601, 지역 시간대). 문서 목록은 이 값이 늦은 것부터 |
| `analysis` | 이 파일을 만든 분석 id(Ocean 학습 화면이 쓴다) |
| `rules` | 이 문서를 뽑은 추출 규칙 판 |
| `edited` | 사람이 고쳤으면 `true`. 다시 저장 때 덮어쓰기 경고를 띄운다 |
| `digest` | 마지막으로 쓴 정해진 부분의 SHA-256([ReadWrite.md §6](ReadWrite.md#6-digest)) |

- 손으로 새 문서 파일을 쓸 때 꼭 있어야 하는 것은 `type` · `id` 뿐이다.
- 모르는 머리글 키는 읽지 않지만 다시 쓸 때 그대로 남는다.

## 2. 본문 — 정해진 부분

라이브러리가 읽고 쓰는 것은 **정해진 부분**뿐이다.

| 자리 | 뜻 |
| --- | --- |
| 첫 `# ` 제목 | 문서 제목 |
| 제목 뒤 첫 `##` 앞의 첫 보통 문단 | 한 줄 요약([ReadWrite.md §2](ReadWrite.md#2-제목과-한-줄)) |
| `## 차례` | 원문의 절 목록(§3) |
| `## 핵심 숫자` | 원문의 대표 숫자(§4) |
| `## 지식` | 카드: 주장 하나와 근거(§5) |
| `## 관계` | 개념 사이의 관계 → [Relation.md](Relation.md) |
| `## 데이터` | 데이터 표 → [DataTable.md](DataTable.md) |

- 절 이름은 같아야 한다. 앞뒤 공백은 빼고 이어진 공백은 하나로 접어 비교한다. 절은 `## ` 줄에서 다음 `## ` 줄 앞까지다. `###` 이하 제목은 절 안의 줄이다.
- Ocean 은 절을 이 순서로 쓰고, 빈 절은 쓰지 않는다. 읽을 때는 순서를 보지 않는다.
- 그 밖의 절과 글은 읽지 않는다. 다시 쓸 때 그 자리에 그대로 둔다.

## 3. 차례

```markdown
- <번호> <절 이름>
  - <번호> <하위 절 이름>
```

- 번호는 공백 없는 글자 하나(`1` · `2.1` · `A`)다. 번호가 없는 줄(`- 소개`)은 읽지 못한 줄이다.
- 들여 쓴 줄은 그 앞에서 마지막으로 읽은 들여 쓰지 않은 항목의 하위 절이다. 사이에 읽지 못한 줄이 있어도 그 항목에 붙는다. 앞에 읽은 항목이 없으면 읽지 못한 줄이다.
- 두 단계까지다. 더 깊은 단계는 다시 쓸 때 둘째 단계로 펴서 쓴다.

## 4. 핵심 숫자

```markdown
- **<값>** <단위> — <설명>
```

- 단위와 설명은 없어도 된다(`- **76.8**`, `- **76.8** — VOC 2007`).
- `—` 는 줄표(U+2014)다.

## 5. 지식(카드)

```markdown
- <주장> <!-- card:<16진수 8자리> -->
  - 근거: <숫자 · 인용>
  - 절: <차례의 번호>
  - 개념: <링크>, <링크>
```

- 카드 id 주석은 다른 편집기에서 보이지 않는다. 16진수는 소문자다. 손으로 쓴 카드는 주석이 없어도 된다(id 가 빈 카드).
- **주장은 한 줄**이다. 안에 굵게 · 코드 · 링크 · `$…$` 같은 줄 안 마크다운은 글자 그대로 들어간다. 쓸 때 줄바꿈은 공백 하나로 바꾼다(주장 아래 목록은 하위 항목과 갈라 읽을 수 없다).
- **근거는 여러 줄 마크다운**이다(§5.1). 한 줄 근거는 지금까지와 같다.
- `개념:` 의 링크가 이 카드가 다루는 개념이다. 지식 사이 보기에서 카드를 개념에 붙일 때 쓴다.
- 없는 하위 항목은 줄을 쓰지 않는다.

### 5.1. 여러 줄 근거

근거에는 문단 · 목록 · 표 · 코드 · `$$…$$` 블록 수식을 쓸 수 있다. 근거 글 안의 줄바꿈은 `\n` 이다.

```markdown
- 상자는 격자 칸과 사전 상자에서 얼마나 옮기고 늘이는지로 예측한다 <!-- card:c4d5e6f7 -->
  - 근거: 상자마다 네 값 $t_x, t_y, t_w, t_h$ 를 낸다. 칸이 $(c_x, c_y)$ 떨어져 있고 사전 상자가 $p_w \times p_h$ 면 상자는 이렇다.

    $$
    b_x = \sigma(t_x) + c_x, \quad b_w = p_w e^{t_w}
    $$

    학습은 제곱 오차의 합으로 한다.

    - 중심은 시그모이드를 거쳐 그 칸 안에 머문다
    - 너비와 높이는 지수라 늘 양수다
  - 절: 2.1
```

**쓰기**

- 첫 줄은 `  - 근거: ` 뒤에 쓴다. 둘째 줄부터는 그 하위 항목의 내용 들여쓰기(공백 네 칸)를 붙여 쓴다. 빈 줄은 공백 없는 빈 줄로 쓴다.
- 첫 줄이 코드 울타리(```` ``` ```` · `~~~`)면 `  - 근거:` 뒤를 비우고 울타리부터 둘째 줄처럼 쓴다. `근거: ` 뒤의 울타리는 블록을 열지 않기 때문이다.
- 쓰기 전에 정리한다(`KnowledgeText::NormalizeEvidence`. 읽기도 같은 정리를 거친다):
  - `\r\n` · `\r` 은 `\n` 으로 바꾼다. 줄 끝 공백 · 근거 앞뒤의 빈 줄은 쓰지 않는다.
  - 한 줄이면 지금처럼 이어진 공백을 하나로 접는다. 여러 줄이면 첫 줄만 접고, 둘째 줄부터는 들여쓰기와 안쪽 공백을 그대로 둔다(코드 · 목록이 깨지지 않게). 첫 줄이 울타리면 첫 줄도 그대로 둔다.
  - 둘째 줄부터(첫 줄이 울타리면 첫 줄부터)의 울타리가 닫히지 않았으면 여는 줄의 들여쓰기 + 같은 글자 셋(```` ``` ```` · `~~~`)으로 닫는 줄을 더한다. 파일의 뒤 절이 코드 안으로 들어가 읽히지 않는 일을 막는다.
  - 그래서 여러 줄 근거는 쓰고 다시 읽으면 정리한 글 그대로다. 줄 끝 공백 두 칸으로 하는 줄바꿈은 남지 않는다(`\` 나 `<br>` 를 쓴다).
- 여러 줄 근거가 하나라도 있는 문서는 `format: 2` 로 쓴다(§1, [Vocabulary.md §5](Vocabulary.md#5-판)).

**읽기**

- `- 근거:` 줄 다음 줄 가운데, 그 `- 근거:` 줄의 들여쓰기 + 2 칸 이상 들여 쓴 줄이 근거의 이어지는 줄이다. 그만큼만 떼고 남은 들여쓰기는 지킨다(공백 여섯 칸 → 두 칸 들인 줄).
- 들여쓰기 칸은 CommonMark 처럼 센다. 공백은 한 칸, 탭은 다음 4의 배수 칸까지다. 그래서 `\t- 근거:`(4칸) 의 이어지는 줄은 6칸(`\t` + 공백 둘, 탭 둘) 이상이고, `  - 근거:`(2칸) 다음의 탭 하나(4칸)는 이어지는 줄이다. 뗄 칸이 탭 가운데에 걸리면 남는 칸은 공백으로 둔다.
- 빈 줄은 **다음 비지 않은 줄이 이어지는 줄일 때만** 근거 안의 빈 줄이다. 아니면 지금처럼 항목을 끝낸다(빈 줄 뒤 하위 항목은 읽지 못한 줄, §6).
- 형제 하위 항목(`- 절:` 처럼 `- 근거:` 와 같은 들여쓰기)이나 덜 들인 줄, 들여 쓰지 않은 줄이 나오면 근거가 끝난다. 덜 들인 줄(`  - 근거:` 다음의 공백 세 칸 줄)은 지금처럼 읽지 못한 줄이고 항목을 끝내지 않는다.
- 더 들인 `- ` 줄(`    - 메모`)은 하위 항목이 아니라 근거 안의 목록이다.
- **울타리**: 이어지는 줄이 코드 울타리를 열고 그 울타리가 닫히면, 닫는 줄까지는 빈 줄 · 들여쓰기와 상관없이 근거다(파일 훑기가 코드로 보는 범위와 같다, [ReadWrite.md §1](ReadWrite.md#1-줄과-범위)). 덜 들인 줄은 있는 만큼만 뗀다.
  - 닫는 줄을 찾다가 카드 구조로 보이는 줄 — id 주석이 있는 카드 첫 줄(`- … <!-- card:… -->`)이나, 근거보다 덜 들인 아는 하위 항목(`  - 절:` · `  - 개념:` · `  - 근거:`) — 을 만나거나 절 안에서 닫히지 않으면, 그 울타리는 위 들여쓰기 규칙대로 읽는다. 손으로 연 울타리를 닫지 않아도 뒤 카드를 삼키지 않는다(Obsidian 에서도 목록 항목이 끝나면 코드가 닫힌다). 다시 쓸 때 닫는 줄을 더한다.
- `- 근거:` 뒤가 비어도 된다. 그때는 이어지는 줄부터가 근거다.
- 관계의 `설명` · `인용` 같은 다른 하위 항목은 한 줄 그대로다. 그 아래 들여 쓴 줄은 읽지 못한 줄이다.

**다른 편집기에서**

- 이 모양은 CommonMark 의 목록 항목 규칙과 같다: 항목 표시(`- `) 뒤 내용 칸만큼 들인 줄은 그 항목에 들고, 그 사이 빈 줄도 다음 줄이 충분히 들여 써져 있으면 항목을 끝내지 않는다. 그래서 Obsidian · GitHub · VS Code 미리보기에서 근거는 `근거:` 하위 항목 아래의 문단 · 목록 · 코드로 보인다. `$$…$$` 는 수식을 그리는 편집기(Obsidian · GitHub)에서 블록 수식으로 보인다.
- 근거 안에 빈 줄이 있으면 그 카드의 하위 목록은 느슨한 목록(항목마다 문단 간격)으로 보인다. 글은 같다.
- 첫 줄은 `근거:` 뒤의 문단이다. 근거를 목록으로 시작하면 첫 항목은 `근거: - …` 문단으로, 둘째 항목부터 목록으로 보인다(글자는 그대로 돌아온다).

## 6. 하위 항목 — 카드와 관계에 같다

- 하위 항목은 공백 두 칸 이상이나 탭으로 들여 쓴 `- ` 줄이다. Ocean 은 두 칸으로 쓴다.
- 첫 `:` 앞이 키, 뒤가 값이다(값은 이어진 공백을 하나로 접는다). 아는 키는 카드가 `근거` · `절` · `개념`, 관계가 `설명` · `위치` · `인용` · `상태` 다.
- 값은 한 줄이다. 카드의 `근거` 만 그 아래 들여 쓴 줄로 이어진다(§5.1).
- **모르는 하위 항목**: 아는 키가 아닌 하위 항목은 콜론이 있든 없든(`  - 메모: …`, `  - 다시 볼 것`, `  - [논문](https://…)`) `- ` 뒤의 글을 앞뒤 공백만 빼고 그 항목에 붙여 둔다. 다시 쓸 때 그 항목 아래, 아는 키 뒤에 그 글 그대로 쓴다.
- 하위 항목은 **바로 앞까지 이어진 항목에만** 붙는다. 빈 줄 뒤나, 읽지 못한 첫 줄(들여 쓰지 않은 줄. `* 주장`, 링크 없는 관계 등) 뒤의 하위 항목은 읽지 못한 줄이다. 손으로 적은 줄이 이웃 항목의 값을 덮지 않게 하려는 것이다.
- Ocean 은 항목 사이에 빈 줄을 두지 않는다.

## 7. 읽지 못한 줄

- 정해진 절 안에서 문법에 맞지 않는 줄은 기록으로 읽지 않고 **읽지 못한 줄**로 둔다. 읽기 결과의 `hashUnreadLines` 에 절 이름별로 담긴다(로그는 남기지 않는다).
- 다시 쓸 때 그 줄은 그 절 끝에 그대로 쓴다. 읽지 못한 줄이 이어진 덩어리 안의 빈 줄은 지킨다(덩어리 앞뒤의 빈 줄은 아니다).
- 그래서 정해진 절 안에 쓴 메모는 잃지 않지만 **절 끝으로 옮겨질 수 있다.** 항목에 붙일 메모는 하위 항목(§6)으로 쓴다.
